# 📘 Assignment: Building REST APIs with FastAPI

## 🎯 Objective

Learn how to build a RESTful API using the FastAPI framework. You'll create endpoints that handle HTTP requests, manage data models, and implement proper validation and error handling — essential skills for modern web development.

## 📝 Tasks

### 🛠️ Task 1: Create Your First FastAPI Application

#### Description
Set up a basic FastAPI server and create your first endpoint. This task introduces you to FastAPI's simple and intuitive syntax for building web APIs.

#### Requirements
Your application should:

- Import and initialize a FastAPI application instance
- Define a simple GET endpoint at `/` that returns a welcome message (e.g., `{"message": "Welcome to my FastAPI!"}`)
- Define a GET endpoint at `/items/{item_id}` that accepts a path parameter and returns it in a JSON response
- Run the server using `uvicorn` and be accessible at `http://localhost:8000`
- Include basic documentation visible at `http://localhost:8000/docs` (auto-generated by FastAPI)


### 🛠️ Task 2: Build a Simple CRUD API

#### Description
Extend your API with Create, Read, Update, and Delete operations using Pydantic models for data validation. You'll manage a simple collection of items in memory.

#### Requirements
Your API should:

- Define a Pydantic model for an `Item` with at least: `id` (integer), `name` (string), and `price` (float)
- Implement a GET endpoint `/items` that returns all items as a list
- Implement a GET endpoint `/items/{item_id}` that returns a single item by ID
- Implement a POST endpoint `/items` that creates a new item and adds it to the collection
- Implement a PUT endpoint `/items/{item_id}` that updates an existing item
- Implement a DELETE endpoint `/items/{item_id}` that removes an item from the collection
- Use appropriate HTTP status codes (200 for success, 201 for created, 404 for not found, etc.)


### 🛠️ Task 3: Add Validation, Error Handling, and Query Parameters

#### Description
Make your API more robust by adding input validation, proper error responses, and optional query parameters. This teaches you how to handle real-world scenarios where data validation and error handling are critical.

#### Requirements
Your API should:

- Add validation rules to your Item model (e.g., `price` must be positive, `name` length constraints)
- Return meaningful error messages when validation fails (leverage FastAPI's built-in validation)
- Implement a GET endpoint `/items` that supports optional query parameters: `skip` (default 0) and `limit` (default 10) for pagination
- Handle the case when a requested item doesn't exist by returning a 404 status code with an appropriate error message
- Add at least one custom endpoint (e.g., `/items/search?q=query`) that filters items based on a search query
- Test your endpoints using the built-in Swagger UI (`/docs`)

## 💡 Tips

- Use `uvicorn app:app --reload` during development to automatically reload when you make changes
- FastAPI's automatic documentation in `/docs` is perfect for testing your endpoints
- Pydantic models make validation automatic — just define your data structure!
- Start simple with Task 1, then gradually add complexity in Tasks 2 and 3

## 🚀 Stretch Goal

Add a database layer (SQLite with SQLAlchemy) to persist data between server restarts instead of keeping items in memory.
